# Repeat-Visit / Premium Asset handoff

## Objective
Build information assets people naturally revisit, monetize them without incentivized ad clicks, and keep responsibility/copyright/operating burden low. Do not treat user-suggested categories as the answer; start from successful market structures and recombine them. Analysis is only useful when it moves an asset through an evidence gate toward launch.

## Current ranking
1. **StackPulse** — primary build. AI/SaaS/cloud reliability + material-change monitoring. Repeat pain, official-source facts, free search pages, paid multi-service boards/alerts/history.
2. **Premium Fare Radar** — conditional build. Premium-economy/business/first-class alerts. High booking intent; launch only with approved commercial fare/affiliate access.
3. **Atlas Privilege / Golf lane** — self-service premium discovery/marketplace experiment. Providers fulfil; members redeem/book directly. No concierge dependency or fabricated private access.
4. **Routine utility network** — time/date/weather/currency/transport only where near-zero-cost data rights are clear.
5. **Public-program/deadline radar** — supporting lane only unless repeat usage and conversion outperform stronger lanes.

## Demoted / incubated
- **Daily Edge** — demoted from primary product to noindex incubator/traffic experiment on 2026-08-26. Keep the asset; do not spend primary build time on it unless measurements justify promotion.

## Patterns taken from successful models
- Timeanddate: free universal utility + responsible advertising.
- Status aggregation: free official-source checks → paid boards, alerts, history and integrations.
- Flightradar24: compelling free live utility → premium depth + business/API layer.
- Flight-deal memberships: free sample → paid premium-cabin alerts.
- Benefit clubs: self-service member benefits and partner economics; fulfilment remains with providers.
- Marketplace/intermediary rule: own discovery, comparison, routing and trust; avoid taking on fulfilment that another provider can safely own.

## Monetization rules
- Never ask/incentivize users to click ads for revenue. Use compliant CPM/CPC inventory only through approved publisher programs.
- Affiliate links must answer an existing user intent (book, compare, redeem, buy); no fake partner IDs.
- Paid membership must unlock recurring utility, earlier alerts, better filtering, saved watchlists or verified benefits—not prestige alone.
- Sponsors/partners cannot buy editorial rankings or fabricated access.

## Premium audience rule
Target calm, self-directed, time-sensitive affluent users rather than high-touch clients. Base membership must work without manual concierge, private-chat moderation or personalized financial advice. Concierge/events can be separately priced later only if economics justify them.

## Hold / kill rules
- Hold live market/gold data unless commercial redistribution rights are explicit.
- Hold premium-flight automation until approved data/affiliate access exists.
- Hold claims of private golf/event/hotel access until real partner rights exist.
- Kill crypto/gambling-first acquisition unless later evidence shows unusually strong risk-adjusted economics.
- Do not spin up a new domain until one lane shows repeat visitors, search impressions, outbound intent, membership interest or sponsor/partner demand.

## Writer Cell rule
Do **not** create a separate Note memo system. When research produces a publishable insight, convert it directly into a ready-to-publish Note draft plus optional X copy and cover-image brief. Store only publish-ready outputs in `content/note-drafts/`. Human-only step remains final note publishing where no supported publishing interface exists. Do not automate note through undocumented endpoints or fragile browser behavior.

## Completion gates
### StackPulse
Official-source ingestion design + rights/terms gate + normalized status model + live/fallback UI + history storage plan + low-frequency scheduler + measurement + Pro waitlist. Do not claim independent monitoring or uptime guarantees.

### Premium Fare Radar
Approved commercial fare/affiliate source must exist before live fares. If unavailable, keep noindex staging and stop engineering. Once approved: alert → fare context → approved airline/OTA link → provider fulfils booking.

### Atlas / Golf
Use only public/authorized offers and booking links. Atlas owns discovery/filtering; golf course/resort/booking provider owns availability, payment, cancellation and fulfilment. Membership can add saved preferences/early curation only after real supply exists.

### Note
Research → Writer → QA → free/paid boundary → title/tags/price recommendation → cover brief/image → publish-ready queue. Use note's supported manual/official scheduling features; final publish remains manual until an official supported write integration is verified.

## Operating rule
Run lanes in parallel, but only add a specialist when a concrete bottleneck appears: source-rights, ingestion, scheduler, measurement, distribution, monetization, editorial QA or premium offer. Once the bottleneck is cleared, stop expanding roles and ship/measure.
