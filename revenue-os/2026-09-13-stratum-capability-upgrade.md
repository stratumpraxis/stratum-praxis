# Stratum Capability Upgrade — 2026-09-13

## Purpose

Strengthen Stratum Praxis by importing only the highest-value capabilities from Forwelle, Production ACE, Publishing, Research, Video, GWR and MARKET without duplicating those departments or creating a competing hierarchy.

The objective remains:

`Payment Evidence > Checkout Evidence > Qualified Buyer Action > Qualified Traffic > Reach`

The preferred path is:

`Existing Asset -> stronger packaging/routing -> verified destination -> qualified human action -> checkout -> payment -> delivery -> attribution -> repeatability`

## Imported capability set

### 1. Forwelle: Existing Asset -> Revenue Media

Use existing Stratum research, products, utilities, proof, data and pages before creating new assets.

For any video/media opportunity:

`Existing Asset -> strongest video-worthy claim -> Hook -> Script -> Visual Direction -> Production -> Distribution -> one Destination -> Revenue Evidence`

Preferred claim types: failure, contrast, number, before/after, unexpected result, buyer pain, evidence, strong verified claim.

A piece of media must have one primary destination. Views alone are not success.

### 2. Production ACE: Revenue-ready production + QA + freeze

Production exists to convert verified demand and existing assets into saleable surfaces, not to maximize output count.

Required production chain:

`Demand Fit -> Buyer Intent -> UI/Visual/Copy/Motion -> CTA -> Existing Offer -> Checkout -> Measurement -> QA -> Freeze -> Handoff`

Before release confirm:
- buyer and use case are explicit;
- rights/licensing are safe;
- destination and checkout are real;
- analytics/attribution are present where technically supported;
- no fabricated proof, outcome or urgency;
- no unnecessary redesign after saleable quality is reached.

Freeze a surface once it is revenue-ready. Reopen only for evidence-backed improvement.

### 3. Publishing: Buyer Angle -> Revenue Route

Publishing is not article-count growth. Convert market/research signals into the angle most likely to move a real buyer toward an existing offer.

Default chain:

`Market Signal -> Buyer -> Buyer Angle -> Brand/Surface -> Content -> CTA -> Existing Offer -> Checkout -> Measurement`

Choose the dominant angle deliberately: problem, result, cost, risk, speed or evidence.

Use verified evidence, numbers, constraints, failures and improvements. Do not publish content with no destination.

### 4. Research: evidence-first demand intelligence

Research must improve a revenue decision.

Prioritize:
- buyer pain with purchase context;
- current market demand;
- competitor gaps;
- pricing/offer context;
- repeated questions/problems;
- evidence that changes which existing Stratum asset should receive traffic.

Research output must end in one of: route existing asset, improve existing asset, hold, stop, or escalate for a new offer only when current assets cannot absorb validated demand.

### 5. Video: reusable visual revenue components

Build reusable motion/visual components around existing Stratum assets: text emphasis, diagram, number treatment, screen demonstration, comparison, evidence frame and end-card CTA.

Video success order:

`Purchase/Contract/Reward -> Checkout -> Buyer Reply/Qualified Action -> CTA -> Qualified Visit -> Human View`

Do not optimize around play count alone.

### 6. GWR: freshness, diff, history and fail-closed

Import GWR's strongest intelligence discipline:
- monitor relevant public sources;
- compare changes/diffs rather than repeatedly rediscovering the same information;
- preserve history;
- mark freshness;
- when freshness/official status cannot be verified, fail closed instead of presenting stale information as current;
- route to official/verified destinations rather than impersonating the final provider.

Use this especially for market demand, opportunity, regulations, provider rules, pricing and platform changes.

### 7. MARKET: cross-route priority and stop control

Use MARKET's controller capabilities without importing MARKET itself.

For candidate work, compare revenue distance across existing routes. The controller may assign:
- `GO` — highest-value safe action now;
- `HOLD` — potentially useful but not current bottleneck;
- `STOP` — duplicate, unsafe, vanity-only or too far from revenue;
- `RESUME` — prior route now has evidence making it worth reopening;
- `KILL` — verified dead/obsolete route, preserving history rather than destructively erasing it.

Do not allocate equal effort across products or channels. Amplify routes that show stronger downstream evidence.

## Ownership protection

Production, Publisher, Asset Brand, Revenue Owner and Checkout are distinct concepts.

Cross-surface distribution is allowed only when brand/account rules permit it, but ownership must not silently change. If a Stratum asset is distributed through another permitted surface, Stratum remains the revenue owner when the offer/checkout belongs to Stratum.

Do not use Vector or other brands merely because they are available when the task is Stratum-specific.

## Gmail / contact guard

Gmail is read-only by default.

Permitted default actions:
- inspect inbox/sent history;
- check replies and buyer evidence;
- detect duplicate/rapid-repeat outreach;
- use email history as evidence for route decisions.

Contact is allowed only when all conditions are true:
1. contact is necessary for the selected revenue-near action;
2. target/recipient fit is verified;
3. there is no duplicate or rapid-repeat contact;
4. message is truthful, low-pressure and policy-safe;
5. an existing Stratum asset/offer solves the identified need;
6. expected value is higher than continuing owned-site/distribution work;
7. the action can be attributed and measured where possible.

If those conditions are not met, do not send.

## Safety-first revenue rule

Prefer owned-site and permission-safe distribution over outbound contact when both can reach the same revenue objective.

Default safe sequence:

`Public demand -> Existing Stratum Asset -> owned/authorized surface -> CTA -> verified checkout -> delivery -> evidence`

Do not use spam, fake engagement, deceptive claims, fabricated outcomes, fake scarcity, prohibited scraping, authentication bypass, unsafe account automation or infinite retries.

## "Next" command protocol

When the owner says `次`, do not merely propose another task.

Each `次` run must do both:

1. **Level-up** — import/apply one useful capability, stronger guard, better evidence method, better routing rule, or reusable revenue component when it materially improves the current system.
2. **Complete** — execute one concrete, non-duplicate, safe action that moves the current highest-priority Stratum route closer to Payment Evidence, then validate and record the result.

Use this loop:

`Current evidence -> identify bottleneck -> choose one capability upgrade -> execute one revenue-near intervention -> validate -> record -> reassess`

Never substitute a capability document, idea list, page count, post count or outreach count for the completed intervention itself.

## Current operating bias

Given existing live products, checkout and indexed revenue pages, prefer:

`Qualified Traffic -> CTA quality -> Checkout -> Purchase Evidence`

over creating new products, broad redesigns or high-volume outreach.
