# Passage Network Playbook

Goal: find and build safe, useful passages between large ecosystems, services, marketplaces, tools, or user journeys instead of competing head-on with the endpoints.

## Search pattern
1. Identify large nodes with existing user demand.
2. Find successful sites/tools that already act as bridges between nodes.
3. Extract the structural pattern: comparison, migration, compatibility, pricing, setup, alternative, calculator, directory, translation layer, status layer, decision support.
4. Map saturated corridors.
5. Find missing, weak, outdated, fragmented, multi-step, or poorly monetized corridors.
6. Build a bounded-responsibility passage.
7. Add a contextual revenue route only where it improves or preserves usefulness.
8. Measure entry traffic, onward CTR, revenue action, repeat use, and maintenance cost.
9. Expand adjacent corridors only after evidence.

## Second-order gap rule
Do not stop at obvious A → B comparisons. Look for gaps between two already-large intermediary ecosystems, directories, comparison surfaces, or user journeys. A strong opportunity may be the missing connection between two networks that each already have demand but force users to search manually across both.

## Valid passage forms
- official change → practical impact
- service A → service B migration
- plan/pricing change → calculator or comparison
- directory → decision tool
- marketplace → compatibility or setup guide
- tool category → workflow-fit finder
- search result → verification / decision layer
- free utility → paid advanced workflow

## Safety boundary
Prefer factual, bounded utility. Avoid professional medical/legal/financial advice, political persuasion, unsupported allegations, scraping-based dependency, deceptive UX, fake urgency, or claims that a passage guarantees outcomes.

## Monetization options
A passage may route to an owned product, paid diagnostic, fixed-scope service, affiliate destination, lead form, membership, sponsor inventory with editorial separation, marketplace listing, or later API/dataset/license path.

## Multi-hub rule
No single permanent home is required. A useful passage can start, end, or pause on different owned or external surfaces. Architecture should follow user intent, friction, evidence, and economics.

## Kill rule
Kill or park a corridor if it adds meaningful maintenance or risk without evidence of qualified traffic, onward clicks, repeat use, conversion, or strategic data value.
