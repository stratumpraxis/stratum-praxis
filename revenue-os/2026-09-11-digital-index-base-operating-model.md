# Digital Index Base Operating Model — 2026-09-11

This file defines operating boundaries only. It does not transfer brand ownership or make Stratum the umbrella brand.

## Umbrella

Digital Index Base is the umbrella structure for the current public asset estate.

## Stratum

Role: B2B asset base with the established independent domain `https://stratumpraxis.com/`.

Keep:
- B2B diagnostics, audits, decision tools, proof, and checkout routes that fit Stratum's B2B role.
- Existing working revenue, analytics, attribution, and deployment logic.

Do not use Stratum as the default home for unrelated consumer/creator experiments. Legacy public assets may remain reachable when preservation is useful, but they should not be re-promoted as core Stratum offers unless they fit the current B2B boundary.

## Vector

Role: general asset base / public hub for non-Stratum assets, creator/practical AI routes, publishing, and reusable public utilities.

Keep existing URLs and useful production assets. Do not duplicate Stratum-owned B2B offers as Vector-owned offers.

## MARKET project

Role: outward revenue circulation.

Primary loop:

`Market Signal -> Buyer -> External Action -> Checkout / Contract -> Payment Evidence -> Learning`

MARKET is judged by movement toward verified revenue, not by volume of pages, posts, messages, or internal activity. Current sales state remains separate from research claims; do not infer revenue without payment evidence.

MARKET should not become the home for exploratory analysis, design experimentation, or page-farm ideation.

## Research project

Role: inward revenue / traffic R&D and free-form experimentation that would otherwise create MARKET noise.

Primary loop:

`Search / SNS / URL / Discovery -> One-page Utility or Diagnostic -> Qualified Visit -> CTA -> Existing Offer / Checkout -> Payment Evidence -> Research Learning`

Research may create and refine one-page sites, utilities, diagnostics, SEO entries, design patterns, and revenue-inflow experiments. Promote a result into MARKET only when there is useful evidence, a clear buyer/revenue route, or an external execution handoff.

Research freedom is intentional, but repeated production mechanisms must remain bounded and observable.

## Two revenue engines

The system therefore has two complementary revenue directions:

- MARKET: outward acquisition and closing.
- Research: inward traffic and revenue-inflow structure.

Neither replaces the other. Shared truth returns through payment/checkout/qualified-action evidence.

## GitHub operating boundary

GitHub is implementation, state, and evidence infrastructure — not a place to accumulate permanent one-shot automation.

Rules:
- Preserve production workflows that still create or verify value.
- Remove or retire completed one-shot workflows when leaving them active creates false failures or notification noise.
- Do not count workflow success as revenue.
- Keep social-account routing fail-closed when the target account is not verified.
- Do not retry suspended/blocked channels automatically.
- Avoid duplicate workflows that perform the same production action.
- Security/vulnerability/bounty work must stay logically separated from normal site, SNS, and revenue operations so unrelated tasks do not inherit unnecessary security context.

## GWR

Global Work Radar is operated as a revenue-inflow website, not as a manual outbound-sales program.

Primary path:

`Inbound Traffic -> Utility / Market Signal -> CTA -> Revenue-bearing Action -> Checkout / Payment Evidence`

Operating rules:
- Use the currently merged GWR redesign as the base for refinement.
- Finish visual/UI quality to the current research-site standard without replacing the concept.
- Reuse existing GWR assets, source policy, tracking, revenue sensors, and monetization logic.
- Do not add new pages/products/features unless a proven gap requires them.
- Gmail outreach, additional manual sales sending, and reply tracking are not the core GWR model.
- Preserve official-source/apply boundaries and fail-closed partner monetization until a verified revenue destination exists.

## Change discipline

For the next operating cycle, change tactics inside these boxes before redesigning the boxes themselves. New ideas should be tested within the current role boundaries first.
