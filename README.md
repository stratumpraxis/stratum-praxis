## Current operating boundary

Keep Stratum focused on B2B assets and buyer decisions. Existing working analytics, attribution, checkout, deployment, and revenue-evidence logic should be preserved.

Do not use Stratum as the default home for unrelated creator, consumer, publishing, or experimental assets. Some historical public URLs may remain reachable for continuity, but legacy assets should not be re-promoted as core Stratum offers unless they fit the current B2B role.

## Revenue truth

Traffic, workflow runs, posts, CTA views, and checkout starts are evidence states, not revenue. Verified revenue requires the relevant payment, transaction, contract, reward, or settlement evidence.

The operating model for Digital Index Base / Stratum / Vector / MARKET / Research is recorded in [`revenue-os/2026-09-11-digital-index-base-operating-model.md`](revenue-os/2026-09-11-digital-index-base-operating-model.md).

## Production discipline

- Prefer existing assets over new offers.
- Fix broken trust, payment, delivery, measurement, or conversion paths before adding scope.
- Keep B2B judgment-heavy or sensitive steps human-controlled where appropriate.
- Preserve stable public URLs when possible.
- Do not reintroduce legacy assets into the main Stratum navigation merely because the files still exist.

The public site remains deployable as plain HTML, CSS, and JavaScript with no build step.
