# Image Signal Upgrade — 2026-08-26

These notes come from user-supplied screenshots of public social posts. Treat screenshots/X posts as market and workflow signals only. Never treat a screenshot claim as verified fact without primary-source confirmation.

## Adopted structural signals

1. Multi-AI orchestration
- Use specialized roles instead of one generic model/process.
- Research, scripting, motion design, rights review, monetization review, contrarian review, publishing verification and analytics learning remain separate responsibilities.
- A model/tool may be substituted only when it improves a defined stage and does not add paid cost without approval.

2. Background / asynchronous work
- OpenAI Responses API supports background responses. Use the concept for long-running research/render orchestration when an API-based implementation is later warranted and budget-approved.
- Current production remains GitHub Actions + official Buffer workflow because it is already verified and low-cost.

3. Agent/subagent/hook/MCP pattern
- Claude Code public materials demonstrate subagents, hooks and MCP as orchestration patterns.
- Adopt the pattern, not vendor lock-in: parallel specialists, pre/post safety gates, deterministic logging, and tool boundaries.
- Hooks or arbitrary shell execution must never be copied blindly from public posts; only trusted reviewed code is allowed.

4. Open-source/code-first editor signal
- Public posts about open-source CapCut-like projects are evidence that code-based editing is becoming practical.
- Do not adopt a project solely because it is viral. Verify license, maintainer activity, security posture and export quality first.
- Existing FFmpeg renderer remains the safe fallback.

5. Higher-quality interface/motion references
- Public design posts show demand for clean interaction, soft depth, large readable type and modern UI motion.
- Translate this into original visual grammar only. Never copy screenshots, logos, creator assets or proprietary UI pixel-for-pixel.

## Candidate advanced render engine

Remotion is the preferred next code-render candidate because it supports programmatic React-based MP4 generation, agentic workflows and motion-design systems. As of 2026-08-26 its published pricing states that individuals and organizations up to 3 people can use the free license with commercial use, subject to its terms. Re-check license terms before material scaling or team growth.

Adoption order:
1. Keep FFmpeg v3 production stable.
2. Prototype one non-published Remotion comparison render.
3. Compare motion quality, render time, failure rate and file size.
4. Adopt Remotion only if visual gain is material and license remains suitable.
5. Never let a new renderer bypass QA, rights, originality or publication verification.

## Content safety / responsibility gate

Do NOT produce or publish:
- unverified breaking-news claims presented as fact
- accusations/allegations about identifiable people
- medical, legal or financial directives
- partisan persuasion or election manipulation
- tragedy exploitation or shock bait
- fake interviews, fake events or realistic deceptive depictions
- celebrity/public-person likeness recreations
- copyrighted TV/movie/anime/game/sports footage
- third-party logos or brand art as generated focal assets
- copyrighted music or unclear-license audio
- scraped/reposted social clips

Prefer:
- tools/workflows explained from official documentation
- creator-economy and AI-production structure
- product/design/workflow principles
- safe technology explainers
- original comparisons and frameworks
- original procedural motion graphics

## Monetization guard

YouTube monetization policy explicitly rejects repetitive/mass-produced/inauthentic template content and image slideshows with minimal value. Each video must be materially different and deliver original creative, educational or analytical value. Rights to commercially use all visual/audio elements must be clear.

The goal is not maximum automatic output. The goal is recognizable authorship at automatic-production speed.
