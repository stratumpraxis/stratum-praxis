# Owner-approved source package: AI agent company control boundaries

This source package supports public derivative writing for Stratum Praxis. It is intentionally a summary, not the paid article.

Core thesis:
Scaling AI-agent systems is not primarily a headcount problem. It is an operating-control problem. More agents increase the number of decisions, permissions, handoffs, context boundaries, and failure paths that must be governed.

Allowed concepts:
- Define an Agent Contract before granting tools or autonomy.
- Use explicit permission levels and Human Gates for consequential actions.
- Keep an Evidence Ledger so important actions can be traced.
- Separate instructions from untrusted data and keep trust boundaries explicit.
- Use hierarchy, routing, segmented memory, and context discipline instead of giving every agent everything.
- Treat Scale/Kill rules as part of operations: scale only agents that are useful and controllable; stop agents whose value is weak or whose failure surface is excessive.
- A useful Company OS can be described as Policy + Memory + Permissions + Routing + Evidence.
- A coordinated agent company is preferable to an unstructured agent swarm when work has real operational consequences.
