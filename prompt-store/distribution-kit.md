## Reply-first engagement patterns
Use replies only where they genuinely solve the original poster’s problem.

If someone asks how to make AI workflows reliable:
> The biggest improvement for me was defining the operating wrapper, not adding more prompt prose: owner, completion condition, failure detection/fallback, QA, and a human approval boundary. That made the same prompt much more reusable across tools.

If someone asks which AI tool should do a task:
> I’d decompose the task first, then assign one primary owner per operation. Research, judgment, deterministic data movement, publishing, and identity/account actions usually should not all go to the same “agent.”

If someone asks how to organize company context:
> Separate verified facts, current decisions, SOPs, metrics, experiments and backlog ideas. Give each class one canonical source of truth and never let AI silently merge conflicts.

Do not add a store link unless the user asks for the full template or the community explicitly permits relevant resource links.
