AI Workflow
Reliability Checklist

A prompt that works once is easy. A workflow that survives messy context, retries, missing permissions and model changes needs stronger operating structure. Use these 10 checks before you automate or scale it.

01

Required context

Are the facts, files, definitions and constraints the system actually needs available and current?

02

Primary owner

Does every operation have one clear Human / AI / Automation / Tool owner?

03

Completion condition

Can the system prove the step is complete instead of merely saying it is done?

04

Verification

Are factual claims, links, calculations and external states checked where needed?

05

Failure detection

Can it distinguish auth failure, timeout, stale data, malformed input and partial writes?

06

Bounded retries

Is there a retry ceiling, backoff and stop condition instead of an infinite loop?

07

Fallback path

When automation cannot safely continue, is there a defined fallback or human queue?

08

Approval boundary

Are destructive, financial, legal, security-sensitive and account actions human-reviewed?

09

State & memory

Does the workflow know what is canonical, what can change, and what must never be silently overwritten?

10

Evaluation loop

Can it detect drift and decide to stop, revise or escalate instead of always optimizing forward?
