The real workflow is bigger than sending reminders.

A document chase usually spans email, a portal or folder, a spreadsheet or practice-management system, client notes, deadlines, and judgment about whether an item is actually usable. Automating only the outgoing email leaves most of the coordination work intact.

Request state
What was requested, when, from whom, and where it should arrive.
Receipt state
What arrived, what is still open, and what needs correction or explanation.
Next action
Which reminder should be prepared, when it should go, and when to stop automation.
Exception state
What needs human context, client-service judgment, or professional review.

A controlled document-collection workflow

  1. Open an approved request list. Start with a defined checklist for the engagement or monthly close.
  2. Send the approved request path. Use the firm's normal secure upload method rather than inventing a new channel.
  3. Track what arrives. Update received / missing / unclear status without treating AI classification as final professional review.
  4. Prepare the next reminder. Draft from an approved template using the current missing-item list.
  5. Require approval where appropriate. Client-facing messages, unusual cases, sensitive items and policy exceptions can pause for a named person.
  6. Escalate stuck cases. Stop automated chasing when the rule says a human should take over.
  7. Close the loop. Mark the request ready only when the firm's completion rule is met.

What should stay human-led?

Automation can coordinate the process; it should not quietly take over professional judgment. A person should remain responsible for decisions such as whether evidence is sufficient, whether an unusual document is acceptable, whether a client explanation resolves an accounting issue, and whether a sensitive or regulated record can be processed through a particular tool.

How to know whether this is worth automating

Do not begin with a software purchase. Begin with the current workflow. Count the repeated touches and put a conservative value on them.

Simple capacity model

monthly files × average follow-up touches × minutes per touch = current coordination time.

Then estimate only the portion that a controlled workflow could realistically remove. Treat the result as a capacity scenario, not guaranteed savings.

Example: a bounded first pilot

A good first pilot is deliberately narrow. Instead of automating every client request, select one recurring document set and one client segment. Define the request list, the accepted upload path, reminder timing, owner, stop conditions and exception rules before any automation acts.

Week 1
Map the existing request and follow-up process. Count touches and failure points.
Week 2
Build the smallest controlled flow using non-sensitive test data.
Week 3
Run representative cases plus missing, late and ambiguous exceptions.
Week 4
Compare handling time, missed follow-ups, exceptions and staff intervention against baseline.

Success criteria before scaling

  • The workflow reduces repeated status-checking or reminder preparation.
  • Staff can see why a case was routed or stopped.
  • Exceptions reach a named owner instead of disappearing inside automation.
  • No production credential or sensitive client record is exposed unnecessarily.
  • The measured benefit is large enough to justify setup, software and maintenance cost.
