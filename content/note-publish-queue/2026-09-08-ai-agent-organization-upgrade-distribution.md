# Newsletter

## Subject
AI社員を増やす前に「就業規則」を作る

## Body
AIにResearch担当、Writer担当、Sales担当と名前を付けると、組織っぽく見えます。

でも本当に必要なのはRole名ではありません。

Role
+ Permission
+ Approval
+ Evidence
+ Escalation
+ Stop

です。

たとえば、Researchは自動でいい。
Production deployは条件付き。
価格変更や契約はHuman Gate。

そして「完了しました」ではなく、RoleごとにEvidenceを決める。

AIを増やすより、今のAIがどこまで自律実行してよく、どこで人間へ渡すかを固定する方が先です。

既存の有料noteへAgent Role Charter、Permission Matrix、Evidence Contract、Failure / Rollback Protocolを追記しました。

# SNS B｜Evidence

Research Agent:
DONE = 調査した
VERIFIED = Source / claim mappingあり

Coding Agent:
DONE = code changed
VERIFIED = test + target state確認

AIの「完了しました」を、Evidence Contractに変える。

Money
Identity
Contract
Sensitive Data
Irreversible Change
High Reputation Risk

この辺だけ明示的に止める。

低リスクの反復作業はAIへ。

# Shorts 1｜30 sec

AI社員を増やす前に、これだけ決める。

何をする？
何をしていい？
何は禁止？
どこで人間承認？
何を証拠にする？
失敗したらどこで止める？

人格設定より、こっちが運用。

---

# Shorts 2｜30 sec

AIの「完了しました」はEvidenceじゃない。

記事完成 → fileあり
公開完了 → public URL確認
コード完成 → testあり
売上 → purchase evidence

Roleごとに完了条件を決める。

# Shorts 3｜35 sec

Agentを増やす条件は1つ。

同じ欠損が何度も起きて、既存Roleでは処理できないことがEvidenceで確認されたとき。

一度しか起きない仕事にAgentを作らない。
