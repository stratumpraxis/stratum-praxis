# Newsletter version

## Subject
AI codingが速くなったのに、売上が速くならない理由

## Body
AI codingを使うと、作る速度はかなり上がります。

LP、記事、Web tool、コード、Checkout、計測。

問題は、作れるものが増えるほど「次に何を作るか」まで軽く決めやすくなることです。

最近、運用を次の順番へ変えました。

```text
市場
↓
GitHub
↓
外部行動
↓
Buyer
↓
Revenue
↓
GitHub
↓
学習
↺
```

GitHubから始めません。

市場でPainやBuyer Signalを確認し、既存Assetで受けられるなら新商品を作らず、Revenueへ1段近づける最小変更だけをCodexへ渡します。

そして、

- BUILD
- SHIP
- SIGNAL
- REVENUE

を分けます。

コードが完成したらBUILD。
公開したらSHIP。
CTAクリックやReplyが出たらSIGNAL。
Purchase / Contract / Rewardが確認できて初めてREVENUE。

「できた」と「売れた」を分けるだけで、次の一手がかなり変わります。

既存の有料noteへ、Codexへそのまま渡せるRevenue Task Templateと7日間Sprintを追記しました。

# SNS Post B｜Anti-build

AIで新しいものを作る前に見るもの。

・既存Assetで受けられないか
・CTAが壊れているだけではないか
・Buyerが本当にいるか
・Checkoutより手前で止まっていないか

AIにとって「作れる」は理由にならない。

市場Evidenceが反復して初めて、新しいAssetを検討する。

# Long Video Script｜5–7 min

## Hook

AI codingが速くなったのに、なぜ売上は同じ速度で増えないのか。

理由の一つは、Codexへ渡している仕事が「制作」で止まっているからです。

## Scene 1｜Old loop

Idea
→ Codex
→ Build
→ Deploy
→ 次のIdea

画面上にはProductが増える。
でもBuyer Signalがない。

## Scene 2｜State separation

BUILD
SHIP
SIGNAL
REVENUE

この4つを大きく表示。

「コードを書いた」
「公開した」
「人が反応した」
「お金が動いた」

全部別物。

## Scene 3｜New loop

市場
→ GitHub
→ 外部行動
→ Buyer
→ Revenue
→ GitHub
→ 学習
↺

市場を一番上へ置く。

## Scene 4｜Revenue task

Codex promptを表示:

このBuyer SignalをRevenueへ1段近づけるために、既存Assetのどこを最小変更すればいいか確認し、実装・Production確認・Evidence保存まで。

## Scene 5｜Don't build

新商品を作らない条件を表示:

既存Assetで受けられる
CTAが壊れている
Buyer未確認
購入Evidenceなし

## Scene 6｜Reality

RevenueはAIが保証しない。

だからこそ、Code VolumeではなくExternal Evidenceを見る。
