# Three-Layer Revenue Architecture

## 1. Autonomous Operations Monitor
Command / Dashboard Layer only.

Owns:
- Current Reality restoration
- Project state display
- Revenue Distance display
- Evidence aggregation
- Human Gate / anomaly display
- Engine launch routing

Does not own:
- Revenue execution
- GitHub task execution
- Engine runtime state

## 2. GitHub ぽちぽち
External GitHub paid-task engine.

Canonical identity:
- codeops.contact@gmail.com
- codeopscontact/codeops

Flow:
Market → Paid Task Discovery → Qualification → Buildable Work → Human Gate → Submission → Accepted → Payout

Success evidence:
- Accepted
- Payout

Its execution state must not be imported into Revenue Pump.

## 3. Revenue Pump
Commercial revenue engine.

Flow:
Market Signal → Revenue Route Selection → First Broken Stage → Distribution → Qualified Human → Buyer Signal → Checkout / Contract → Payment → Fulfillment → Repeat Revenue

Success evidence:
- Payment
- Payout
- Cash Evidence

## Shared only
- Market Signal
- Revenue Evidence
- Payout Evidence
- Learned Pattern
- Current Status

## Never shared
- GitHub Identity
- Gmail Identity
- Secrets
- External Write Authority
- Runtime
- Execution State
- Project-specific settings
